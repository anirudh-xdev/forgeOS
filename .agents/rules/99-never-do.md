# Prohibited Practices & Hard Redlines
*Explicit prohibitions that must never be violated under any circumstances.*

---

## The Prohibited Redlines

1. **NEVER expose secrets**: Never print API keys, database credentials, or secret tokens into prompts, logs, artifacts, or code commits.
2. **NEVER commit `.env` files**: Never add `.env` or files containing live credentials to version control.
3. **NEVER delete user work**: Never run commands that wipe unstaged changes or delete user files without explicit, verified permission.
4. **NEVER force push**: Never run `git push --force` or overwrite remote branch history.
5. **NEVER reset the repository**: Never execute `git reset --hard` or `git clean -fd` across the workspace.
6. **NEVER bypass tests or linter**: Never pass `--no-verify`, `--skip-tests`, or disable lint rules (`eslint-disable`) to force a build to pass.
7. **NEVER weaken validation to make broken output pass**: Never relax Zod schema constraints to accept corrupted LLM responses. Fix the prompt or generation pipeline.
8. **NEVER execute untrusted generated code on the host**: Never run `npm install`, compile code, or run test suites generated by LLMs on the main host. Always isolate inside Docker sandboxes.
9. **NEVER introduce infrastructure without justification**: Do not add Kafka, Kubernetes, or vector databases when PostgreSQL, Redis, and Docker are specified for v0.1.
10. **NEVER add an agent without a defined contract**: Never create an agent consisting solely of a prompt. Every agent must have an `AgentDefinition`, input/output schemas, and failure modes.
11. **NEVER create circular dependencies**: Monorepo packages must maintain strict unidirectional dependency trees (`contracts` → `ai-provider` / `database` → `agent-runtime` → `orchestrator`).
12. **NEVER couple agents to specific providers**: Never import `openai`, `anthropic`, or `ollama` SDKs directly into agent implementations. Always consume `AIProvider`.
13. **NEVER silently change architecture**: If a design decision deviates from `docs/forgeos-spec.md`, it must be documented as an ADR and approved.
14. **NEVER claim success without verification**: Never declare an implementation complete without running typecheck, lint, and relevant automated tests.

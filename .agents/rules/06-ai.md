# AI Engineering Rules
*Enforcing untrusted output handling, structured validation pipelines, and execution tracking.*

---

## 1. Core Principle: LLM Output = Untrusted Input

ForgeOS is an engineering platform, not an LLM wrapper. Agents must never treat output from any language model as correct, complete, or secure.

### The Mandatory 4-Stage Output Pipeline
All structured output produced by any model must traverse this pipeline without exception:

```text
[ Raw LLM Output ]
       ↓
  1. GENERATE
       • Invoke AIProvider.generate(request) with prompt & schema guidance
       • Track latencyMs, inputTokens, outputTokens, cost
       ↓
  2. VALIDATE
       • Parse JSON safely (catch syntax errors)
       • Validate against target Zod schema in packages/contracts
       • If invalid: emit validation error context and trigger bounded retry
       ↓
  3. NORMALIZE
       • Sanitize strings, strip markdown code fences (` ```json `), prune invalid fields
       • Format numbers, trim whitespace, ensure deterministic IDs
       ↓
  4. PERSIST
       • Save to database as an Artifact record with status "draft"
       • Record execution metrics in AgentRun
       • Emit ARTIFACT_UPDATED domain event
```

---

## 2. Guardrails Against LLM Non-Determinism

1. **Strict JSON Schema Enforcement**: Prompts must instruct models to output valid JSON only. Where the provider supports it, enforce native structured output or JSON mode.
2. **Schema Rejection over Compromise**: If an LLM response violates the schema, reject it. **Never weaken a schema to make a broken LLM response pass.**
3. **Bounded Retries with Error Context**: When validation fails:
   - Provide the exact validation errors (`zodError.issues`) back to the model in the retry prompt.
   - Limit retry attempts to `maxRetries` (default: 3).
   - If retries are exhausted, fail the `AgentTask` and notify the orchestrator.
4. **Timeouts**: Every LLM generation call must have an enforced timeout (default: 120s for local Ollama, 60s for cloud providers) to prevent worker hanging.
5. **Cost & Token Tracking**: Every call must capture `inputTokens`, `outputTokens`, `latencyMs`, and estimated cost. Record these in `AgentRun`.

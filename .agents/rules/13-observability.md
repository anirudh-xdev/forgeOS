# Observability & Metrics Rules
*Standards for AgentRun instrumentation, execution timelines, telemetry, and structured logging.*

---

## 1. Mandatory Execution Metrics (Specification Section 18 & 22)

Every LLM generation and agent task execution must be comprehensively measured.

### Required Fields in `AgentRun`
Whenever an agent runs, the runtime must capture:
- `id`: UUID of the execution run.
- `taskId`: Associated `AgentTask` ID.
- `provider`: Resolved AI provider name (`ollama`, `openrouter`, `mock`).
- `model`: Target model identifier (`llama3:8b`, `claude-3-5-sonnet`, etc.).
- `startedAt` & `completedAt`: High-resolution timestamps.
- `latencyMs`: Elapsed generation time in milliseconds.
- `inputTokens`: Token count sent in the prompt.
- `outputTokens`: Token count generated by the model.
- `costUSD`: Estimated monetary cost based on provider pricing tables.
- `queueTimeMs`: Time spent waiting in the BullMQ queue before pickup.
- `status`: `running` | `success` | `failed`.
- `error`: Serialized error message and stack trace if failed.
- `retries`: Attempt number for this task run.

---

## 2. Structured Logging & Telemetry

1. **JSON Logging**: All system logs must be emitted as structured JSON (via Pino in `packages/logger`), including correlation IDs (`traceId`, `projectId`, `taskId`).
2. **OpenTelemetry Spans**: Every agent execution, queue job, and database transaction must be wrapped in an OpenTelemetry span.
3. **Timeline Events**: Important milestones emit `DomainEvent` records that drive the live UI timeline.
